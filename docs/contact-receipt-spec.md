# B07a/B07b 問い合わせの受付保存

対象は既存 `/api/contact` と3つの呼出しフォーム。現行 main bfa76e0 を基準とし、共有 checkout の未コミット変更には触れない。既存 `inquiries` を再利用し、schema・認証・保存期間・通知先の変更は行わない。

## 入出力と成功条件

- 検証済み入力を先に保存し、保存した受付番号が得られた場合だけ HTTP 200 / `ok:true` を返す。入力値や内部IDは応答へ含めない。
- 通知と自動返信は保存後に実行。Resend の error、例外、IDなし応答は送信確認失敗。provider 受理は受信箱への配達確認とは区別する。
- メール失敗や状態更新失敗で、保存済みの受付を失敗に戻さない。pending/failed は既存の所有者専用受付画面で確認・通知再送できる。新しい無人再送は開始しない。
- 3フォームは内容が変わらない再試行に同じ UUID を用いる。キーはフォームのメモリ内だけに保持する。DB 一意制約と入力の digest を使い、同じキーで違う内容なら409。別エンドポイントとの衝突を避けるため保存キーには contact/v1 の接頭辞を付ける。
- 古い開きっぱなしのフォームからキーなしで来た場合は、サーバーで UUID を生成して受け付ける。この互換経路は通信断後の二重送信を防げないので、本番前の確認項目に残す。
- 保存結果不明なら、クライアントは同じキーで再照合する。サーバーは保存の例外を成功と推測しない。
- 保存列は既存の business/category/locale/source_path/payload/consent_share と通知状態。自由記述は非公開 payload だけ。GA には氏名・連絡先・本文・受付番号・キーを送らない。
- 入力本文と各フィールドに上限を設け、既存レート制限を使用する。送信元パスのクエリ・ハッシュを削除。Notion・Drive・広告DBへ転送しない。
- 一般フォームの成功計測は受付番号を得た後だけ。表示される受付番号はサーバー保存の証拠であり、受任や成約ではない。

## 受入試験

保存失敗時はメール0回・成功応答なし／保存後の送信例外でも受付を保持／status更新失敗でも受付を保持／同一キー再試行・競合で二重登録通知なし／同一キー別内容409／他endpointキーとの分離／電話のみの既存受付／不正JSON・長すぎる入力・制限超過／本文・エラー・キーの非流出／管理画面の詳細と通知再送／3フォームの再試行キーと受付番号確認／既存回帰。

実DBは列定義とRLS・権限だけ読取り確認し、顧客データの閲覧・試験登録・実メール送信は行わない。Previewと本番の実運用確認は別工程。

## 適用前の残件と限界

- Main と異なる共有 checkout には、コラム・物件の `context` を問い合わせに渡す未コミット変更がある。本変更へ無断で取り込んでいない。同変更を採用する際には入力契約・通知・保存の各項目を統合し、捨てられないことを試験する。
- フォームを閉じたり再読込みするとメモリ内の送信キーは失われる。キーなし旧クライアントも含め、全ての再訪・内容変更を同一人物の同一相談と自動統合するものではない。
- 受付番号は保存結果の照合用。既存のGAイベントはクライアント側の補助計測であり、最終の受付件数は保存された受付を根拠とする。クリック・受任・メール配達完了を同一指標にしない。
- Resend の idempotency は公式資料上24時間。DB保存後のプロセス終了では通知が pending のまま残り得る。所有者の受付画面で原結果を確認してから再送する。自動再送キュー・配達確認・CRMへの受任連携は今回含まない。
- 受付保存は既存のサーバー接続を使う。Preview が本番DBを参照していないことを確認するまで、フォーム送信による実地試験はしない。マイグレーションは不要だが、実行先のテーブル・権限・既存インデックスは読み取りで再確認する。
- 新旧クライアント・APIを異なる版へ巻き戻すと、受付番号のない応答を新フォームが拒否する。ロールバックは同一デプロイのUI/APIを一緒に戻し、既に保存された受付は削除しない。
- 自動返信は既存の受付メール部品を再利用し、自由記述を返信へ複写しない。UIの受付番号と保存期間案内は4言語、メール本文の言語は既存同様の日本語。
- 根拠: [Resend Send Email](https://resend.com/docs/api-reference/emails/send-email)、[Idempotency Keys](https://resend.com/docs/dashboard/emails/idempotency-keys)。今回のローカル試験はDB・配信サービスを置換したもので、本番での保存・配達の証拠とは区別する。
