# 文京区のポータル直接検索

## 2026-09-25改訂：掲載条件は「仲介手数料＋AD 80万円以上」（ユーザー指示）

ITANJI・いい生活だけで完結させる。REINS・元付への承諾確認は行わない。

1. 文京区・広告掲載可・申込なし・現在募集中を取得元の認証済み画面で確認する。
2. 「賃料×1.1（仲介手数料税込）＋AD」が80万円以上の号室だけを新規登録する。ADは月数・%・万円・円の表記を円に換算する（外税・内税の調整はしない）。「相談」「まで」「迄」など確定しない表記は保留。「ADなし」は0円。
3. 旧方針の「募集条件更新24時間以内」と「賃料20万円以上」は新規登録の条件にしない。
4. `intake.policy` は `bunkyo-income800k`。旧方針 `bunkyo-rent200k-ad30-or-rent250k` は登録済み物件の再確認だけに使い、新規登録は拒否する。
5. 公開後の自動非表示（確認期限切れでの非公開）は行わない。`availabilityExpiresAt` は再確認の目安。成約・募集終了は定期の再確認で取得元の終了を確認して `close` する。
6. メール起点のAD2ヶ月ルートは従来どおり。

## 旧方針（2026-09-23、再確認用の履歴）

ユーザー指定の「いい生活と同じ条件」をITANJIにも適用する。メール起点の従来AD2ヶ月ルートは維持し、直接検索ではメールの架空記録を作らない。

1. 文京区・賃料20万円以上・募集条件更新24時間以内・広告掲載可能で検索する。
2. 詳細収集の前に申込ありを除外する。ITANJIは申込数1以上が対象外、空欄は進める。いい生活は「申込なし」を確認する。
3. 賃料20万円以上25万円未満はAD30%以上。25万円以上はADなし・記載なしでも対象。
4. 同一号室の広告可・募集中と取得時刻を記録する。ITANJI詳細の「広告掲載可否 可」も肯定表記として扱う。広告料と広告許可は別の判定。
5. 建物名・所在地・号室・取得元IDで既登録を除外する。終了物件を再公開しない。
6. 詳細が参照を指示する元付資料で不足条件を補完し、出典と原文を `supportingDocuments` に残す。古い募集図面と最新詳細の価格が異なる場合は最新の詳細表示を採用する。条件の不整合を勝手に解消せず、既存の未確認表示に関する指示に従って明示する。
7. ギャラリーの拡大元画像を全部取得し、番号・枚数を照合する。元付帯付き図面、基準未満の小画像、重複は理由を残して除外する。画像手順は `../rental-image-automation.md` を参照。
8. 管理画面を通じてアップロードする場合は対象号室自身の下書き画面を使う。他物件の編集画面を一時アップロード用に流用しない。
9. 写真・間取りを自社ストレージに保存し、日本語・英語・繁体字・簡体字の全文と条件欄を照合する。公開前に `contentReview` と公開検証を実行する。
10. 公開画面で画像枚数・重複・解像度・全言語の費用条件・QA・内見CTAを確認する。物件データの登録のためにVercelの全ページを再生成しない。
11. 明示された広告有効期限が確認期限より早ければ、その期限までに公開期間を短縮する。次回ログイン時は現在の募集状況を再確認し、申込・掲載終了なら非公開にする。認証切れを募集終了とみなさない。

## 確認データ

`intake.kind` は `portal-search`、`intake.policy` は `bunkyo-rent200k-ad30-or-rent250k`。
`intake.updateEvidence` は認証済み画面で同一号室を照合した記録とし、`quote` に表示ラベルと相対時間を記録する（例：`募集条件更新 7時間前`）。実測していない更新日時を作らない。画面確認時からの経過も24時間判定に含める。初回登録時の絞込みと既登録物件の募集再確認は分け、再確認では現在の掲載証拠を取り直す。

従来ルートでは引き続き実際のメール記録が必要。広告不可、募集終了、取得元の照合不成立、確認期限切れは直接検索でも通さない。
