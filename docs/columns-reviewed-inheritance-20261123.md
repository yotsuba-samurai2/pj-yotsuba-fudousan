# 国際相続コラム5本の既存公開稿訂正

対象は #534 で原稿を公開用に整理した固定5記事のみです。新規作成・全件seed・再公開を行う画面ではありません。権限追加は不要です。

1. 配備したコミットを確認後、既存のサイト管理者アカウントでログインします。コラム管理の「国際相続5本の確認・訂正」を開き、「対象5本を読み取り確認」。この操作は読取りだけです。
2. 配備前の原稿と一致した対象だけに、言語別の変更前／確認稿を表示します。資格者の確認・承認および対象記事の原本バックアップを済ませてから、対象ごとに確認欄を選び、「この1本を訂正して保存」。確認後にどの版が変わっても再照合が必要です。差し替え先の文書をブラウザから貼り付ける機能はありません。
3. 1本ずつ保存します。別の記事の競合により、すでに保存した記事を自動で元に戻すことはありません。止まった場合は、残りに進む前に一覧を再取得し、公開中の状態も確認してください。
4. 各対象の実公開ページで本文、要約、FAQとFAQの構造化データ、HTTP 200、canonical/hreflang、サイトマップ更新を確認します。管理者画面の「訂正済み」は原稿一致であり、外部検索インデックスや配備済みの公開表示を保証するものではありません。

## 保存の仕組みと停止・戻し方

サーバーで事業・slug固定、通常管理者認証、同一オリジンの書き込み、公開日／公開言語／公開状態、現行・確認稿の指紋、更新時刻を照合します。保存は既存行IDの楽観ロック付きです。公開日・公開言語・公開状態、著者・タグ等は書き換えません。反映済みの再試行は無変更で終了します。

HTTP 409 は競合です。人の編集を上書きせず再取得・再照合。HTTP 503 で mutationSucceeded が真ならDBは保存済みで公開更新だけ失敗した状態なので、再送せずCMSと公開表示を先に確認します。

戻す必要がある場合、この画面に任意入力や取り消しボタンはありません。資格者と管理者で、事前に退避した変更前の材料を使い、同じ5件のうち実際に反映した必要な1件ずつを対象とする逆方向の確認稿を作ります。現行が確認稿の版のままかを再取得・照合し、認証済み既存の限定訂正経路で更新時刻を条件に戻し、同様に公開表示を確認します。全件seed・直接DB書き込み・古い証跡の再利用は行いません。

既存の更新処理による公開キャッシュ再検証とIndexNowは変えていません。別途の索引送信はこの手順に含めません。固定5レコードのデータは `python3 scripts/build-reviewed-inheritance-20261123.py`（変更前・承認済みコミットの履歴が必要）で再現可能です。
