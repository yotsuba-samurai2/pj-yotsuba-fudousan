# luck428.com 3サイト改善・検証記録（2026-09-18）

## 実装範囲

対象は `/`・`/legal`・`/labor`。実際の公開コードを持つ `pj-yotsuba-fudousan` の3経路を、共通部品も含めて修正した。元のチェックアウトは変更せず、`origin/main` の `cecba09` から分離した `perf/site-health-20260918` ブランチで作業した。

- 高優先度ヒーロー画像の `decode()` 完了と2フレームの描画機会を先に確保してからフォントを読み込む。現在使う文字・ウェイトの読み込みを待って、2書体をまとめて適用する。フォント失敗時は読める既存フォールバックを維持する。
- モバイル幅（767px以下）のトップ本文のセクションと共通フッターに `content-visibility: auto` を適用。画面外のレイアウト・描画を延期し、高さの仮置きと描画済み高さの記憶を使う。HTMLの本文は保持し、印刷時には描画延期を解除する。フォント準備処理も描画対象外の部分を読み込まない。PCでは仮高さが背景装飾を動かす副作用を確認したため、描画延期の対象から外した。
- 不動産の桜画像を既存の許可品質60で配信。横長ロゴの `sizes` を実表示幅146px／205pxへ合わせた。背景装飾はServer Component化した。
- 共通ヘッダーに `X-Frame-Options: SAMEORIGIN` と `Content-Security-Policy: base-uri 'self'; object-src 'none'; frame-ancestors 'self'` を追加。
- 不動産・行政書士のFAQ専用ページを4言語ともh1に修正。共通FAQ部品の既定はh2とし、他のページ内FAQと構造化データを保つ。

## 未使用JS/CSSの扱い

公開サイトの切り分けでは、未使用JS推定約100 KiBの主な内訳はGoogle Analytics約75 KiBとReact系チャンク約29 KiBだった。初期ネットワークとソースで、チャット本体は既に遅延読み込みされていることを確認した。チャットを主因と断定して再分割していない。

未使用CSS推定約64 KiBは、ほぼ2書体の日本語フォント定義だった。実際には多数のフォントファイルが使用されており、推定未使用量をそのまま削ると日本語・中国語の表示範囲を損なう。Tailwindの走査範囲をsrcに限定した比較でもCSSサイズは変わらなかった。このため文字集合・書体・React・解析機能を削らず、適用順序と画面外の処理を見直した。新しい制御処理のためJS/CSS本体には少量の増加もある。主な成果は初期処理時間と画像・初期フォント転送の削減である。詳細な転送バイト数は添付JSON/CSVに記録した。

PR提出時、GitHub DependabotのopenアラートをAPIで確認した。計29件（Critical 2・High 14・Medium 12・Low 1）。今回の差分では依存関係を変更していないため、これらは未解消。

- [AVIF画像最適化時のRCE](https://github.com/vercel/next.js/security/advisories/GHSA-2xp9-vwfh-vxw4)：sharp/libheifでAVIFを最適化する条件。対象画像の配信最適化だけではこの問題は解消しない。

両アラートが示す16系の最初の修正版は16.3.3。現行lockfileは16.2.10。依存関係更新と互換性検証を優先して別途実施する必要があり、本PRのみでサイトの安全性を保証できない。
