# 会社先頭の観測充足率（ローカル履歴契約）

`placement-coverage.ts` はR05用。アットホームで同じ部屋を掲載する会社のうち、対象の会社/店舗が先頭かを扱う。検索結果の物件順位を代用しない。観測を実行するschedulerやブラウザ操作は含まない。

## 予定と実績を分離

観測開始前の計画id/version/hashに、物件・募集回・媒体掲載revision/hash・会社/店舗・PC/スマホWeb/アプリ・観測条件と予定slotを固定。contextは公開先区分、ログイン状態、地域・絞込み・並び順・queryの確認済み参照を持つ。不明値の既定補完はしない。

slotは重ならない`[start,end)`、観測時刻はslot内、受領時刻は観測以降かつ検査時点以前。全計画期間終了後だけ集計する。途中集計は未対応として保留。計画hashは呼出元の信頼できる保管から渡す必要があり、同じ入力からhashを作っただけでは事前確定を証明しない。

同一ID/内容の再送だけdedup。同じslotの別観測、ID再利用、別slotへの同じ証跡参照の使い回しは保留する。勝手に最新観測を選ばない。別時点に同じ公開内容が見えてもcontentHashが一致すること自体は重複証跡と扱わない。

## 分母と欠測

- `expectedSlots`：固定計画の予定数。
- `validObservedSlots`：公開済み・同一部屋・対象会社/店舗・同一部屋会社一覧・内容hash・取得根拠が確認され、先頭yes/noが明示された観測数。
- `firstSlots` / `notFirstSlots`：有効観測内の先頭/非先頭。
- `observationCoverage`：有効観測÷予定数。
- `firstShareAmongValid`：先頭÷有効観測。有効観測0ならnull。

未観測、読取り失敗/CAPTCHA/再認証、観測範囲内の対象未発見、非公開、公開不明、先頭不明はそれぞれ理由を保持。有効観測の分母にも非先頭にも補完しない。`periodEnded:true`は時間経過だけを示し、観測の充足や成功を表さない。

## 残る境界

旧媒体状態の最新観測とは別の履歴契約であり、現在の掲載版へ過去結果を読み替えない。実会社/部屋照合、根拠の真正性、信頼できる計画保管、媒体観測adapter、業務の必要充足率/継続期間・交換scopeは未確認。全結果`executable:false`、`decisionEligible:false`。公開成功・先頭目標達成や自社サイト停止の判断には接続しない。
