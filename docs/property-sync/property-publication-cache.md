# 募集終了等の公開依存先の失効（unit24）

通常管理CRUDはブラウザ側の追加revalidate通信に依存していた。その経路は全pathへlocaleを付けるため、rootのsitemap.xmlも/ja/sitemap.xml等になっていた。取込APIはroot sitemapを指定していたが、依存一覧・記事は対象外で失効完了も待っていなかった。

保存成功後に共通`refreshPropertyPublication`を呼ぶ。通常POST/upsert/PATCHと取込apply/closeが対象。入力拒否/CAS競合/check/check-close/画像upload/下書き削除には呼ばない。before/afterの物件slugを全localeの内部pathへ展開、一覧、サービス/中国語案内の逆リンク、学区一覧/特集/売買/賃貸、realestate記事の動的page pattern、prefixなしsitemapを失効要求する。記事の個別関係台帳がまだないためrealestate記事pattern全体を対象とし、他事業layout全体は失効しない。

元13変更にあるRelatedPropertyListingsは作業repoへ混ぜず、その依存先を動的記事patternで包含。既存の記事本文/関係の書換えや別物件へのredirectを追加しない。詳細・学区ページの既存force-dynamicと公開allowlistを維持する。

Nextの同梱revalidatePathガイドを参照し、rewrite後の内部path、動的patternのpage指定、次回アクセスでの再生成を使用する。既存のcolumn側が使うflushRevalidationを共有し、完了を待つ。失効失敗は503・mutationSucceeded:true・publicationRefresh:failedと「保存済み、再保存せず再読取」の固定message。通知記録と既存の通知予約は保存後に維持し、cache失敗で書込みを再実行しない。

既存クライアントの追加revalidate呼出しは互換性のため残すが、この処理の成否はそれに依存しない。内部flushはNext固定versionに依存する既存実装であり、今回ネットワーク/本番cacheは操作していない。CLIなどrequest外の保存、別APIの保存経路、第三者cache、既に開いたタブの再読取、再生成後の画面照合と伝播時間記録は未検証/別作業。失効要求の完了を公開反映済みと呼ばない。

unit26追補：一覧画面の成約handlerが保存済みmessageを汎用失敗へ置換する問題を修正。実API clientのmessageを保持し、失敗時はGETで状態再取得する。PATCH再送はしない。再読取も失敗したら現在状態を推測せず取得エラーを表示。確認文から即時反映の保証を除去。
