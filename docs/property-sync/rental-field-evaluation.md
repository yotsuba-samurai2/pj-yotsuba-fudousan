# 賃貸候補の限定的な条件判定（unit23）

`evaluateRentalFields` は既存の履歴選択 `resolveRule` を使い、指定scopeの現行ルールと、独立した意味設定の版/hashに固定して、正規化済みの賃料・居室数・K/DK/LDK・借家種別を照合する純粋関数。旧B01や公開gateは置換せず、実データ/外部接続/公開処理はない。

賃料下限/上限・居室数・借家種別はルールから取り、履歴上の17〜27万円等を既定値にしない。賃料に管理費を含めるか、境界を含めるか、K/DK/LDKの許容集合、service roomを居室数に含めない意味、正規化契約は別の承認済み設定で明示する。設定がnullなら判定を止める。意味設定も同一scope内で最新開始済み版を選び、新版pending/失効から旧版へ戻らない。個別顧客・売買・事業用へ継承しない。

管理費込みの場合の欠測は0と扱わない。金額は月額JPY整数の入力契約でBigInt加算。税換算・別の費用加算・単位変換は行わない。1SLDKを2部屋にする推測や原文解析は行わない。areaは既存ルールのpreferredAreaSqmなので、未達でも必須条件不適合に変えず希望充足を別に返す。

`fieldVerdict` は4条件だけの一致/不一致/未知。確実な不一致と未知が併存する場合は不一致とし、各未知もchecksに残す。常にexecutable:false、eligibilityConfirmed:false。学区・当社報酬/税・許諾・素材安全性は未評価のgate。結果へ住所/本文/生の金額/内部報酬/顧客参照を出さない。これは公開APIでもない。

呼び出し側は現在のsource全体hash・募集回/物件binding・証拠hash・ルール/意味設定hashを独立して渡す必要がある。hash一致は真正性を証明しない。正規化確認や観測時刻の自己申告を信頼できる入力へ変えるreader、入力契約の承認、意味設定履歴の完全性、実在物件からの抽出は未実装。別時点のfieldをまとめる際に新しい観測時刻へ付け替えてはならない。

実設定が未確定のため、現行の一般募集条件はここでは選ばない。合成fixtureの100〜200円等は試験用である。B01への実統合、他市場、学区/内部収益判定、掲載判断は別の作業。

## unit45：版付きの追加条件

上記は旧4項目契約。新しいpolicyは`additionalChecks`を明示して、間取りごとの最低面積、元掲載情報の更新期間、ADを含む当社総額を追加評価できる。値はpolicy/ruleから取得し、ソースへ業務の閾値を固定しない。追加設定が未確定なら保留する。旧policyのhash・出力は維持し、旧policyへ新証拠を渡した場合は黙って無視せず停止する。

- `minimumArea`は居室数の下限とK/DK/LDKの集合に該当する物件へだけ適用する。必須面積と`preferredAreaSqm`の希望を分離し、対象外は`not_applicable`。対象外でも既存の間取り・賃料・借家条件が免除されるわけではない。1LDKの採用例を全1LDKや3K等へ一般化しない。
- `sourcePropertyUpdate`は取得元の掲載情報が更新された時刻と根拠。観測・再取得・ローカルDB編集時刻は代用不可。時刻付きデータの経過時間を包含境界で比較する。日付しかない場合はtimezone/日付解釈を別に確定するまで入力を受理せず、観測後の更新時刻も拒否する。証拠そのものの鮮度`maxEvidenceAgeHours`とは別条件である。
- 当社総額は第5引数の非公開証拠から取得し、既存ruleの閾値と税基準を使用する。物件・募集回・source hash・証拠hash・正規化・観測鮮度・根拠・確定状態を照合する。ADを別に加算する項目は受理せず、税込/税抜の自動換算や条件付き報酬の確定扱いは行わない。総額や根拠IDは結果へ返さない。

追加契約の`fieldVerdict`はこれらの条件を含むが、引き続き`eligibilityConfirmed:false`・`executable:false`。一致は根拠の真正性や全体の掲載適格性を証明しない。実学区の定借例外・募集/広告/素材許諾・本番反映は別gate。具体的な本人条件は作業領域の私有入力に保存し、本番historyへ適用していない。

## 条件と配分の継続改善

本人は条件を固定せず、検証結果をもとに変更する方針を指定した。1LDKの初期割合も掲載集合の配分目標であり、個別物件の適格性を緩める条件ではない。媒体・分母・時点・端数処理が未確定なら件数配分を計算しない。

候補条件を別版として比較し、変更理由・対象・評価期間・欠測・反響/受任/収益・採用根拠を残す。`resolveRule`の履歴選択とhash固定、既存計測/監査/評価lockの部品を再利用する。戻す場合も旧履歴を消さず、旧内容を新しい版として記録する。条件変更と同時に期待値や評価基準を緩めて成功に見せない。

現時点の`evaluation-integrity`は評価ファイルの一致確認であり、改善案の評価・自動採用・本番rollbackまで実装済みではない。今回も自動最適化runnerや実媒体操作を追加していない。

## unit46：報酬総額による選択・間取り集合・定借の学区例外

過去の節の未確定値は[最新の確認差分](operating-decisions-delta.md)を参照。ruleの`rentSelectionBasis`を`company_income_total`と明示した場合だけ、賃料上下限を両方nullとして総額判定へ進める。旧範囲の混入はエラー、旧版や`rent_range`のnullは従来どおり保留。総額基準は`additionalChecks.incomeBasis`が必要で、報酬証拠なしはunknown。賃料は範囲判定対象外でも正規化済み値が必要であり、欠測を既知扱いしない。管理費別の設定では管理費の欠測/大小は賃料判定に影響しない。

`layoutAlternatives`は居室数の範囲とkitchen集合のORで、既存の最小居室数/許容kitchen条件とのAND。1LDKと2DK以上を別の集合に設定し、1DK/3Kを意図せず含めない。1LDKは最低面積の対象外でも更新期間・報酬・借家などの条件を満たす必要がある。エンジンへ固定の賃料・面積・割合・校名を埋め込まない。

`fixedLeaseSchoolException`は自治体・小学校集合・年度・適用日を設定する。全域でfixedを許容するruleとの同居は保留。普通借家は従来の判定を保ち、定借では第6引数の私有証拠（request/address/dataset/expectedDataset）とrequestのhashを要求する。証拠なしはunknown、未確定の適用年月や不正証拠は保留。

既存`matchSchoolEvidence`を再実行し、正規化住所・公式範囲表・完全性・曖昧行を照合する。さらに物件/募集回/source hash・観測前のsource版・自治体・小学校・年度・適用日を照合し、設定集合外はoutsideとする。完成済みmatchの自己申告は入力として受理しない。普通借家や未設定policyへ学区証拠を渡して黙って無視することもない。

結果には追加の証拠hashだけを残し、生住所・校名・報酬を返さない。`SCHOOL_SCOPE`等の全体gateと`executable:false`・`eligibilityConfirmed:false`は維持する。ここでの一致は本番の採用決定・学区保証・公開許可ではない。実ルール履歴/媒体/改善runnerへの接続は未実施。
