# 現行の受信期間・採算条件

2026-10-26、本人の「受信7日以内・税込報酬総額20万円以上を上書き」に基づく置換。設定記録時刻は2026-10-26 09:25:34 JST（00:25:34 UTC）。コードが本番へ反映された事実とは区別する。

| 項目 | 現行値 |
|---|---|
| 新規メールの受信期間 | 判定時点から168時間以内。境界を含み、未来・不正日時は拒否 |
| 採算の下限 | 当社報酬総額200,000円以上。ちょうど20万円を含む |
| 総額の意味 | ADを含む当社報酬の総額・税込・確定額 |
| 未確認 | 総額・税込・確定額・対象との対応・確認者・根拠が不明なら保留 |
| 計算しないもの | 総額へのAD再加算、賃料からの借主手数料推計、税区分不明の換算 |

設定正本は `rental-import/adoption-policy.ts` の `CURRENT_RENTAL_ADOPTION_POLICY`。旧scan、新取込候補箱、通常のimport、公開前検査で利用する。今後の自己改善は、値を直接書き換え続けず、評価・差分・独立レビュー・採用履歴・戻し方を伴う版変更として扱う。

旧入力の `bunkyo-income800k` / `eslife-new-income400k` / `bunkyo-p033-income300k` 等を送っても、現在の採算条件は変わらない。旧閾値の計算関数は設定記録時刻より前の判断を再現するためだけに残す。実API/CLIは実行時刻を渡す。過去日時を指定したテストの成功を現在の採用成功としない。

## 報酬根拠の入力

通常の取込JSONに `companyIncome` を追加する。`totalYen`、`basis: company_total_including_ad`、`taxBasis: included`、`certainty: confirmed`、確認者ref、既存 `evidence` 形式の原文/参照/確認日時を持つ。確認日時は既存の根拠鮮度（24時間以内）を維持する。

根拠は同一のprovider / roomId / 明示された建物・住所・号室に結び付ける。メール経由はmessageIdも一致させ、直接検索はnullとする。AD原文だけから総額の根拠を作らない。追加の報酬内訳・税推定の入力を別途合算する経路はない。

成功時の設定版と報酬根拠は `internal.rentalImport` に保存するpayloadへ含める。公開用データは既存allowlistだけを通す。メールから自社サイト/ATBBへ直送しない。

## 維持する境界

- 受信7日と物件情報更新14日は別条件。受信日で物件更新日時を更新しない。
- 既存掲載の再確認は、元メールが古くなっただけで停止しない。現在の総額根拠は必要。
- 既存公開ページを条件変更だけで一括非公開にしない。古い根拠の物件は次の更新/公開前検査で新しい根拠が必要になる。
- 事業用・売買へ賃貸の採算条件を自動流用しない。広告許諾、募集確認、画像、公開本文検査など他のゲートは維持する。
- 四葉の共通DBを正本とし、その既存IDと媒体別掲載処理を維持する。

このコード変更だけで実物件の報酬を確認したことにはならない。旧payloadに新しい根拠がなければ現在の更新は保留されるため、適用時は確認記録を準備する。本番データの取得・書換えや外部連絡は今回行わない。
